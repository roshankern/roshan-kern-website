# Hardware reference — SO-101 follower arm + iPhone 17

Reference dimensions for building a to-scale three.js figure. Every number below is either
read directly out of a published CAD/URDF/MJCF file, quoted from a vendor spec page, or
explicitly marked **[ESTIMATE]** with the derivation shown.

**Primary source of truth for the arm:** `Simulation/SO101/so101_new_calib.urdf` in
[TheRobotStudio/SO-ARM100](https://github.com/TheRobotStudio/SO-ARM100), raw file at
<https://raw.githubusercontent.com/TheRobotStudio/SO-ARM100/main/Simulation/SO101/so101_new_calib.urdf>
(last touched 2025-07-02, commit `385e8d7`). It is generated by `onshape-to-robot` from the
official Onshape document
<https://cad.onshape.com/documents/7715cc284bb430fe6dab4ffd/w/4fd0791b683777b02f8d975a/e/826c553ede3b7592eb9ca800>.

**Units note:** the URDF works in metres; the referenced STL meshes are also in metres
(no `scale` attribute). All values below are converted to millimetres.

**Sanity check against the known bounding box (532 × 173 × 111 mm):** transforming every
visual mesh through the URDF kinematic chain and searching joint space for the maximum
vertical extent gives **536.8 × 110.9 × (169–177) mm** — i.e. 111 mm is exactly the base
plate width (110.93 mm), ~532 mm is the arm fully extended vertically, and ~173 mm is the
horizontal depth in that upright pose. The URDF is confirmed as the correct model.

## 1. Kinematic link lengths, joint offsets, axes and limits

### 1.1 Joint offsets as written in the URDF

Each row is the `<origin xyz rpy>` of that joint relative to **its parent joint's frame**
(not the world). `|offset|` is the straight-line distance, which is the number you want for
link length. Source for every row:
[so101_new_calib.urdf](https://raw.githubusercontent.com/TheRobotStudio/SO-ARM100/main/Simulation/SO101/so101_new_calib.urdf)

| # | Joint | Parent → Child | Local offset x, y, z (mm) | \|offset\| (mm) | Local rpy (rad) | Axis (local) |
|---|-------|----------------|---------------------------|-----------------|------------------|--------------|
| 1 | `shoulder_pan` | `base_link` → `shoulder_link` | 38.835, 0.000, 62.400 | **73.50** | 3.14159, 0, −3.14159 | 0 0 1 |
| 2 | `shoulder_lift` | `shoulder_link` → `upper_arm_link` | −30.399, −18.278, −54.200 | **64.78** | −1.5708, −1.5708, 0 | 0 0 1 |
| 3 | `elbow_flex` | `upper_arm_link` → `lower_arm_link` | −112.570, −28.000, 0.000 | **116.00** | 0, 0, 1.5708 | 0 0 1 |
| 4 | `wrist_flex` | `lower_arm_link` → `wrist_link` | −134.900, 5.200, 0.000 | **135.00** | 0, 0, −1.5708 | 0 0 1 |
| 5 | `wrist_roll` | `wrist_link` → `gripper_link` | 0.000, −61.100, 18.100 | **63.72** | 1.5708, 0.04868, 3.14159 | 0 0 1 |
| 6 | `gripper` (jaw) | `gripper_link` → `moving_jaw_so101_v1_link` | 20.200, 18.800, −23.400 | **36.18** | 1.5708, 0, 0 | 0 0 1 |
| — | `gripper_frame_joint` (fixed TCP) | `gripper_link` → `gripper_frame_link` | −7.900, −0.218, −98.127 | **98.45** | 0, 3.14159, 0 | fixed |

The three "clean" numbers are the real printed-link lengths: **112.57 mm** (upper arm) with a
**28.0 mm** perpendicular jog, **134.90 mm** (forearm) with a **5.2 mm** jog, and
**61.10 mm** (wrist) with an **18.1 mm** jog.

|-------|-----------------------------|------------------------------|------------------------|
| `shoulder_pan` | 38.84, 0.00, 62.40 | 73.50 | (0, 0, −1) — vertical yaw |
| `shoulder_lift` | 69.23, −18.28, 116.60 | 64.78 | (0, 1, 0) — pitch |
| `elbow_flex` | 97.23, −18.28, 229.17 | 116.00 | (0, 1, 0) — pitch |
| `wrist_flex` | 232.13, −18.28, 234.37 | 135.00 | (0, 1, 0) — pitch |
| `wrist_roll` | 293.23, −0.18, 234.37 | 63.72 | (−1, 0, 0) — roll |

Straight from the `<limit lower= upper=>` tags in the same URDF. All joints

|-------|-------------|-------------|-------------|-------------|-------------|
| `shoulder_pan` | −1.91986 | 1.91986 | −110.00 | 110.00 | 220.0 |
| `shoulder_lift` | −1.74533 | 1.74533 | −100.00 | 100.00 | 200.0 |
| `elbow_flex` | −1.69000 | 1.69000 | −96.83 | 96.83 | 193.7 |
| `wrist_flex` | −1.65806 | 1.65806 | −95.00 | 95.00 | 190.0 |

### 1.4 Cross-check against MuJoCo Menagerie (SO-ARM100)

[google-deepmind/mujoco_menagerie `trs_so_arm100/so_arm100.xml`](https://raw.githubusercontent.com/google-deepmind/mujoco_menagerie/main/trs_so_arm100/so_arm100.xml).
This is the **SO-ARM100**, the previous generation, and it uses a different frame convention,
but the load-bearing link lengths are identical, which is a strong confirmation.

| Quantity | SO-101 URDF (mm) | Menagerie SO-ARM100 (mm) | Agree? |
|----------|------------------|--------------------------|--------|
| Upper arm (`elbow_flex` offset) | 112.57 / 28.0 | 112.57 / 28.0 (`pos="0 0.11257 0.028"`) | ✅ identical |
| Forearm (`wrist_flex` offset) | 134.90 / 5.2 | 134.90 / 5.2 (`pos="0 0.0052 0.1349"`) | ✅ identical |
| Wrist (`wrist_roll` offset) | 61.10 / 18.1 | **60.10** (`pos="0 -0.0601 0"`), no 18.1 jog | ⚠️ **differs by 1.0 mm** and Menagerie drops the 18.1 mm offset |
| Jaw pivot | 20.2 / 18.8 / 23.4 | 20.2 / 24.4 (`pos="-0.0202 -0.0244 0"`) | ⚠️ differs |
| Base → shoulder | 38.835 / 62.4 | 45.2 / 16.5 (`pos="0 -0.0452 0.0165"`) | ⚠️ different base frame origin |

**Where they disagree, use the SO-101 URDF** — it is the model for the arm you are building
and it is what reproduces the 532 mm bounding box.

Joint ranges also differ slightly because the zero conventions differ
(Menagerie: `Pitch` −3.32…0.174, `Elbow` −0.174…3.14, `Wrist_Roll` ±2.79, `Jaw` −0.174…1.75).

Menagerie also ships two named keyframes worth using as poses:
`home` = `0 −1.57 1.57 1.57 −1.57 0` and `rest` = `0 −3.32 3.11 1.18 0 −0.174`.

### 1.5 Old vs new calibration file

`so101_old_calib.urdf` and `so101_new_calib.urdf` contain **the same link magnitudes**
(112.57/28.0, 134.9/5.2, 61.1/18.1, 20.2/18.8/23.4). They differ only in link naming
(`wrist` vs `wrist_link`), in the zero-pose rotations baked into `rpy`, and in the new file
adding the `gripper_frame_link` TCP and a 0.04868 rad tilt on `wrist_roll`.
Use **`so101_new_calib.urdf`**.
[old](https://raw.githubusercontent.com/TheRobotStudio/SO-ARM100/main/Simulation/SO101/so101_old_calib.urdf) ·
[new](https://raw.githubusercontent.com/TheRobotStudio/SO-ARM100/main/Simulation/SO101/so101_new_calib.urdf)

## 3. The servos

The SO-101 follower arm uses **6 × Feetech STS3215**, all the same variant: **7.4 V,
1/345 gear ratio (part code C001)**.
Sources: [SO-ARM100 README / BOM](https://github.com/TheRobotStudio/SO-ARM100) ·
[Hugging Face LeRobot SO-101 docs](https://huggingface.co/docs/lerobot/so101)
("The follower arm uses 6x STS3215 motors with 1/345 gearing").

Only the **leader** arm mixes gear ratios (1/191 for pan and elbow, 1/345 for shoulder lift,
1/147 for wrist flex, wrist roll and gripper) — the follower does not.
Some resellers ship a 12 V variant (C018/C044) instead of the 7.4 V C001; the body
dimensions are the same.

### 3.1 Body dimensions

| Dimension | Value (mm) | Source |
|-----------|-----------|--------|
| Length | **45.2** | **Feetech, manufacturer** — "45.2X24.7X35mm", [feetechrc.com](https://www.feetechrc.com/2020-05-13_56655.html); also [servodatabase.com](https://servodatabase.com/servo/feetech/sts3215) |
| Width | **24.7** | same two sources |
| Height (body only, no horn) | **35.0** | same two sources |
| Length (CAD mesh) | 45.40 | `sts3215_03a_v1.stl` bbox |
| Width (CAD mesh) | 24.80 | same |
| Height incl. output horn boss (CAD mesh) | 39.60 | same |
| Weight | 55 ± 1 g | [RobotShop STS3215 listing](https://www.robotshop.com/products/feetech-12v-30kgcm-magnetic-encoding-servo-sts3215) |

for the body and add a 4.6 mm horn boss.**

|----------|-------|--------|
| Spline | **25 T**, OD **5.9 mm** | [RobotShop](https://www.robotshop.com/products/feetech-12v-30kgcm-magnetic-encoding-servo-sts3215) / [servodatabase](https://servodatabase.com/servo/feetech/sts3215) |

| Axis position along the 45.4 mm length | **10.2 mm from the near end / 35.2 mm from the far end** (i.e. +12.50 mm from the body centre) | derived: `shoulder_pan` axis at world x = 38.84, servo mesh spans world x 3.64…49.04 |
| Axis position across the 24.8 mm width | centred | mesh |

**Both faces carry a horn.** The assembly guide says for every joint: *"Install both motor
horns. Secure the top horn with a M3×6 mm screw. No screws are required for the bottom
horn."* — the driven output spline on one face, a free-spinning idler horn on the opposite
face, so a link can be pinned on both sides.
([LeRobot SO-101 assembly](https://huggingface.co/docs/lerobot/so101))

There is also a `sts3215_03a_no_horn_v1.stl` in the asset folder; its outer bounding box is
identical (45.40 × 24.80 × 39.60), so for visual purposes the two are interchangeable.

## 4. Visual construction — how the arm is actually built

**Material and finish.** Every structural part is FDM 3D-printed in **PLA+**, printed with a
0.4 mm nozzle at 0.2 mm layer height (or 0.6 mm nozzle at 0.4 mm layer), **15 % infill**,
supports everywhere but ignoring slopes over 45°. Recommended printers are the Prusa MINI+,
Ender 3 and Bambu Lab machines. That means visible layer lines at roughly 0.2 mm pitch,
flat chamfered shells, and slightly rounded printed edges — not smooth injection-moulded
tubes. Source: [SO-ARM100 README](https://github.com/TheRobotStudio/SO-ARM100).

**Colour.** The URDF declares two render materials
([so101_new_calib.urdf](https://raw.githubusercontent.com/TheRobotStudio/SO-ARM100/main/Simulation/SO101/so101_new_calib.urdf)):

| Material | RGBA | Hex | Applies to |
|----------|------|-----|-----------|
| `3d_printed` | 1.0, 0.82, 0.12, 1.0 | `#FFD11F` amber/yellow | all printed shells |
| `sts3215` | 0.1, 0.1, 0.1, 1.0 | `#1A1A1A` near-black | all six servos |

Physical reference builds are most often printed in plain **white or light-grey PLA+**;
the amber is the simulator's render colour, not a required filament colour. Either reads
correctly, but the black servos against a lighter shell is the defining visual contrast.

**Link construction — yes, two parallel plates sandwiching a servo.** This was verified by
slicing the actual STL meshes. Taking `upper_arm_so101_v1.stl` and cutting perpendicular to
its long axis, the cross-section is two separate solid slabs with a clear air gap between
them:

| Slice location along the 142 mm arm | Plate 1 thickness | Gap (channel) | Plate 2 thickness |
|---|---|---|---|
| elbow end | 6.7 mm | **33.7 mm** | 9.6 mm |
| shoulder end | 13.5 mm | **36.4 mm** | 13.5 mm |

The 33.7–36.4 mm channel is exactly the servo's 35.0 mm body height. So each link is a
**clevis / fork**: two flat printed cheeks, 6.7–13.5 mm thick, straddling a servo that drops
into the channel between them, bridged along the back by a spine. The cheeks bolt to the
servo's two horns — *"Attach the upper arm with 4 M3×6 mm screws on each side"*, and
similarly *"Connect the forearm to motor 3 using 4 M3×6 mm screws on each side"*
([assembly guide](https://huggingface.co/docs/lerobot/so101)). Overall the link is
~24.5 mm thick, ~50–67 mm across the cheeks, and 142 mm long.

**Where the servos sit.** One servo per joint, six total, each fully visible:

1. Base — servo lies horizontal inside the printed base box, output shaft pointing up (this is `shoulder_pan`).
2. Shoulder — servo held in `motor_holder_so101_base_v1`, driving `shoulder_lift`.
3. Elbow — servo in the top of the upper arm fork.
4. Wrist flex — servo in `motor_holder_so101_wrist_v1`.
5. Wrist roll — servo in `wrist_roll_pitch_so101_v2`.
6. Gripper — servo inside the fixed jaw body `wrist_roll_follower_so101_v1`.

Servos are daisy-chained with visible 3-pin cables running along the outside of the links —
a real visual feature of this arm. A Waveshare bus servo driver board is bolted to the base
on a 51 × 42 × 7.6 mm printed plate.

**Gripper shape.** Single-acting parallel-ish claw, not a two-finger parallel gripper.
`wrist_roll_follower_so101_v1` (65.2 × 52.0 × 105.4 mm) is the **fixed** jaw and also houses
the gripper servo; `moving_jaw_so101_v1` (22.3 × 92.0 × 48.0 mm) is a single curved printed
finger that pivots about the `gripper` joint from −10° (slightly over-closed) to +100° (open
wide). The jaws are long and tapered — roughly 90 mm of jaw beyond the pivot. The Menagerie
MJCF models the fixed jaw's grip face as four contact pads at 57.2, 76.8, 91.4 and 101.4 mm
from the jaw origin, confirming a long flat gripping surface rather than a point contact.
([so_arm100.xml](https://raw.githubusercontent.com/google-deepmind/mujoco_menagerie/main/trs_so_arm100/so_arm100.xml))

**Fasteners visible on the surface:** M3×6 mm socket screws at every horn (4 per side per
joint) and M2×6 mm screws holding each servo into its holder (4 per servo). These read as
small dark dots in a regular 4-point pattern on each cheek.
